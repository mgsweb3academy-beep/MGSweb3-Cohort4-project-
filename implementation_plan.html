Goal Description

To transition the Corridor LMS from a scaffolded prototype (with mocked data) into a fully functional, production-ready application. This plan outlines the necessary steps to implement the 14 parts detailed in CORRIDOR-PRD-14-PARTS_1.md, focusing on database integration, authentication, GitHub webhook ingestion, and the AI agent architecture.

User Review Required

IMPORTANT

The current codebase has the UI components (packages/ui) and basic routing (apps/web, apps/api) scaffolded, but it relies entirely on in-memory mock data (e.g., CoursesService returns hardcoded arrays). The database layer and the AI service (apps/ai-service) have not been created yet. Please review the implementation order below.

Open Questions

WARNING
  1. Database Setup: The PRD specifies PostgreSQL + Prisma. Should we initialize this using a local Docker setup, or do you have a hosted database (like Supabase or Neon) ready?
  2. AI Architecture: The PRD mentions apps/ai-service using Python + LangGraph. I plan to initialize this as a FastAPI backend within the monorepo. Does this align with your expectations?

Proposed Changes

1. Database & Infrastructure

  • [NEW] packages/db: Initialize a shared Prisma schema to be consumed by apps/api and apps/web (if needed for NextAuth).
  • Data Modeling: Define Prisma models for User, Program, Cohort, Team, Course, Lesson, Task, Enrollment, and Contribution.
  • [MODIFY] apps/api/**/*.service.ts: Strip out all hardcoded arrays and replace them with real database queries using the Prisma client.

2. Authentication & Onboarding (Part 2)

  • [MODIFY] apps/web/app/api/auth/[...nextauth]/route.ts: Fully configure NextAuth with GitHub OAuth and Credentials providers, linking to the Prisma database.
  • [MODIFY] apps/api: Implement JWT/Session validation guards to secure all endpoints based on user roles (student, instructor, admin).

3. Git Integration & Contribution (Part 6)

  • [NEW] apps/api/src/webhooks: Create endpoints to ingest GitHub push, pull_request, and pull_request_review events.
  • Contribution Engine: Implement the composite score logic (files touched, surviving lines, reviews given) rather than raw commit counts, updating the Task and Contribution records.

4. AI Services (Parts 8 & 9)

  • [NEW] apps/ai-service: Initialize a Python FastAPI project.
  • LangGraph Agents: Build the Supervisor (Manager), Review Agent, Progress Coach, and Tutor agents.
  • Internal API: Establish a secure communication channel between apps/api (NestJS) and apps/ai-service (Python).

5. Frontend & UI Polish (Parts 3-5, 10-12)

  • [MODIFY] apps/web/app/**/*: Connect the mocked frontend pages (Dashboard, Board, Queue, Split, Admin) to the newly functioning apps/api endpoints.
  • State & Real-time: Ensure the UI correctly reflects task state transitions triggered by webhooks or the AI Manager.

Verification Plan

Automated Tests

  • Run unit tests for the NestJS services to ensure CRUD operations and role-based access control work correctly.
  • Write integration tests for the GitHub webhook parser to verify it correctly updates Task states (Pushed, In Review, Closed).

Manual Verification

  • Complete an end-to-end user journey: Register -> Join Cohort -> Assign Task -> Trigger Mock GitHub Push -> Verify Contribution Matrix Updates -> Verify AI Manager logs an action.
  • Test the AI Tutor chat interface in the Student Dashboard to ensure it grounds responses in the course content.
