03

Give it a database

Right now every restart wipes every user, task and course. There is no persistence layer of any kind — the whole product is React state over mock arrays.

 6 items
Write the Prisma schema and first migration No schema, no migrations, no Postgres anywhere in the repo. PRD §4 requires the schema to mirror packages/types exactly, so step 02 has to land first.
Replace the in-memory auth store with real tables Users, invites, enrollments and reset tokens are four new Map() objects in module scope. On serverless, consecutive requests can land on different instances and see different data. apps/web/lib/auth-store.ts:29-33
Move the task store off a module-level array Every task mutation writes to let taskStore = [...MOCK_TASKS]. Create a task, redeploy, it's gone. apps/web/app/api/v1/tasks/route.ts:16
Back every NestJS service with the database All seven Nest services hold a private seeded array. Suspending a user through the admin panel is forgotten on the next deploy. apps/api/src/courses/courses.service.ts:5 (and 6 sibling services)
Stand up Redis and move the rate limiter onto it The limiter keeps its counters in a local map, so it resets on cold start and counts separately per instance. PRD §6 asks for Redis-backed, per-user, per-endpoint limits — especially on the AI routes. apps/web/lib/rate-limit/rate-limiter.ts
Point the twelve pages that read MOCK_* directly at the API The dashboard, task board, admin panel, cohorts and programs pages all import seed arrays from lib/mock-data.ts into component state and never call an endpoint. dashboard · tasks · admin · cohorts · programs · lessons
04

Close the security holes

None of these are acceptable with one real learner on the platform, let alone a cohort of forty-one.

 7 items
Hash passwords — they are stored and compared in plaintext Registration writes passwordHash: input.password and login compares user.passwordHash === password. The seeded accounts have the literal passwords admin, instructor and student. PRD §6 requires Argon2 or bcrypt. apps/web/lib/auth-store.ts:118 · :137 · :203
Remove the hardcoded fallback session secret AUTH_SECRET falls back to the string 'dev-corridor-secret'. If the env var is unset in production, anyone who reads this repo can forge an admin session token. apps/web/auth.ts:9
Add RBAC guards to the NestJS API — every endpoint is currently open There is no guard, no decorator, no auth middleware in apps/api. PUT /admin/users/:id/suspend answers an unauthenticated request. PRD §6 requires RBAC on every endpoint. apps/api/src/admin/admin.controller.ts
Constrain CORS and read the port from the environment Bare app.enableCors() allows any origin. The port is hardcoded to 3001, which Render and Railway both override — the service will bind the wrong port and fail its health check. apps/api/src/main.ts:6-7
Replace the hardcoded localhost:3001 calls in the admin panel Ten fetches point at localhost. The admin panel breaks the moment it is deployed anywhere. apps/web/app/admin/page.tsx:340, 367, 383, 581, 683, 694, 706, 909, 919
Add .env.example and fail fast on missing variables No env file or example exists. GITHUB_ID, GITHUB_SECRET, GOOGLE_ID and GOOGLE_SECRET are all unset, so both OAuth buttons fail at runtime today with no useful error.
Confirm GitHub OAuth actually works end to end GitHub identity is not optional here — it is how submission works. The provider is configured but has never been run against real credentials, and Part 6 depends entirely on it. apps/web/auth.ts:12-24
05

Build the ship pipeline

There is no automation of any kind in the repo — no container, no workflow, no deploy target.

 6 items
Add a GitHub Actions workflow that typechecks and tests every PR No .github/ directory exists. Part 14's acceptance criteria name this explicitly, and it is what would have caught the broken build weeks ago.
Write a Dockerfile and a docker-compose for local dev Compose is what gives every one of the fourteen contributors the same Postgres and Redis instead of a different local setup each.
Pick and configure the deploy targets PRD §4 suggests Vercel for the web app and Railway, Render or ECS for the API. No config for any of them is present.
Give the NestJS API a health endpoint The web app has one; the API has none, so no platform can tell whether it came up. Part 14 also requires that an AI-service outage degrade gracefully rather than take down auth, courses and tasks. apps/web/app/api/health/route.ts exists · apps/api has no equivalent
Wire up error monitoring No Sentry, no Prometheus, no logging destination. Without it, the first production failure is invisible until a learner reports it.
Reconcile docs/API.md with what is actually implemented The contract document exists at 295 lines and roughly 40 routes — it was written on time, which is more than most cohorts manage. But nothing has been checked against it since, and it now describes endpoints in both backends. docs/API.md
Gate 2 — Product Gate 1 gets a safe, persistent LMS onto the internet. This is what makes it Corridor rather than a generic course shell.
06

Build the four things that define the product

Product Direction §1 names four things that define Corridor: team collaboration, submission by push, git contribution tracking, and an AI task manager. Three of the four have no implementation.

 6 items
Part 6 — Git integration and contribution tracking The single largest gap. No GitHub App, no webhook receiver, no branch-per-task convention, no composite contribution score. The ContributionMatrix component renders numbers typed by hand into a seed file. Without this, "turning it in is a push" is a slogan the product does not implement. no octokit, no webhook handler, no contribution service anywhere in the repo
Part 7 — Peer review and the submission workflow No review interface, no approve / request-changes actions, and nothing enforcing the rule that a task needs two approvals before it can close. Depends on Part 6 for commit data.
Part 8 — the AI manager, review agent and progress coach The manager's log line on the student dashboard — "Flagged Team 4 — one member wrote 82% of the contribution" — is a hardcoded string in the JSX. Nothing produces it. This is the MVP criterion that says the manager must generate one real flag during a live cohort. apps/web/app/dashboard/page.tsx:178
Part 9 — connect the AI routes to an actual model The four AI endpoints and their UI are built and shaped correctly, which is real progress. But lib/ai-service.ts contains zero network calls — no fetch, no API key, no provider. Answers come from a three-lesson library and keyword matching. Swapping in a real model is a contained job now that the interface exists. apps/web/lib/ai-service.ts — no fetch, no process.env
Part 15 — light/dark theme and wallet connection Nothing exists: no prefers-color-scheme handling, no theme toggle, no wagmi or WalletConnect. The spec for it was written and merged, but no code followed.
Add object storage for lesson assets and submitted files S3 or R2 per PRD §4. The video and PDF viewers in packages/ui are built and waiting for somewhere to read from.
